Audioopname via Finly niet teruggevonden – troubleshooting in browser

Finly › Instellingen en configuratie (voor beheerders) › Klanten · bijgewerkt 22 juni 2026

Stap-voor-stap handleiding voor het terugvinden van een audioopname via de browsertools in Edge, Chrome en Safari, inclusief hoe je herkent of een opname niet correct is opgeslagen.

Introductie

Als een audioopname via Finly Record niet zichtbaar is na het opslaan, wil je als eerste controleren of het bestand nog aanwezig is in de browsercache — voordat je de browser afsluit of hard refresht. Een harde refresh of het afsluiten van de browser verwijdert tijdelijk opgeslagen data en maakt herstel onmogelijk.

Gebruik in plaats daarvan een gewone refresh (F5 of Ctrl+R) om de pagina opnieuw te laden zonder de cache te wissen.

Deze handleiding beschrijft hoe je in Edge, Chrome en Safari de browsertools gebruikt om de opname terug te vinden, te herkennen en eventueel te downloaden.

Belangrijk: doe dit eerst

  • Sluit de browser niet af en doe geen hard refresh (Ctrl+Shift+R / Cmd+Shift+R). Dit wist de cache.

  • Een gewone refresh (F5 of Ctrl+R) is wel toegestaan.

  • Open de DevTools met F12 of via het menu → Meer hulpprogramma's → Ontwikkelhulpprogramma's.

Microsoft Edge

1. Network-tab – actieve verzoeken en uploads

  1. Open DevTools (F12) → tabblad Network.

  2. Zet het filter bovenaan op Media.

  3. Vernieuw de pagina met F5.

  4. Kijk in de kolom Name naar bestanden met extensies als .webm, .ogg, .opus, .mp4 of .wav.

  5. De kolom Size toont from disk cache of from memory cache als het bestand uit de cache wordt geladen.

  6. Klik op het verzoek → tabblad Headers → zoek naar Content-Type: audio/... om te bevestigen dat het een audiobestand is.

Upload herkennen: Zet het filter op XHR of Fetch. Zoek naar POST-verzoeken met een grote payload (kolom Size). Dit is doorgaans de upload van de opname naar de Finly-server.

Downloaden: Rechtsklik op het verzoek → Opslaan als.

2. Application → Cache Storage

  1. DevTools → tabblad Application.

  2. Klik in het linker menu op Cache Storage (onder Storage).

  3. Vouw de cache-namen uit en zoek naar entries met een audioextensie of Content-Type: audio/.

  4. Kopieer de URL van de entry → open in nieuw tabblad → rechtsklik → Opslaan als.

Hier staan bestanden die via een Service Worker zijn gecached.

3. Application → IndexedDB

  1. DevTools → Application → linker menu → IndexedDB.

  2. Vouw de databases en object stores uit.

  3. Zoek naar entries met een blob- of audiotype in de waarden.

Sommige apps bufferen opnames hier tijdelijk voordat ze uploaden.

4. Application → Storage (overzicht)

  1. DevTools → Application → klik bovenaan op Storage.

  2. Dit toont een overzicht van alle actieve opslagmechanismen: Cache Storage, IndexedDB, Local Storage, Session Storage.

  3. Gebruik dit als startpunt om te bepalen waar je verder moet zoeken.

Google Chrome

De werkwijze in Chrome is vrijwel identiek aan Edge. Alle tabbladen (Network, Application, Cache Storage, IndexedDB) zijn op dezelfde manier te vinden en werken hetzelfde. Gebruik F12 om DevTools te openen.

Filters, kolomnamen en downloadmethode zijn identiek aan de beschrijving bij Edge hierboven.

Apple Safari

  1. Activeer eerst de ontwikkelaarsmenu: Safari → Instellingen → tabblad Geavanceerd → vink aan: Toon het menu Ontwikkelen in de menubalk.

  2. Open Web Inspector via Develop → Show Web Inspector (of Opt+Cmd+I).

  3. Tabblad Network: filter op Media (icoon met noten) → zoek naar audiobestanden op dezelfde manier als bij Edge.

  4. Tabblad Storage: hier vind je Cache Storage en IndexedDB, vergelijkbaar met het Application-tabblad in Edge/Chrome.

  5. Downloaden: Rechtsklik op het netwerkverzoek → Download Response.

Let op: Safari's DevTools zijn minder uitgebreid dan Edge/Chrome. Niet alle cache-entries zijn direct downloadbaar.

Hoe herken je een Finly audioopname?

  • Bestandsformaat: .webm, .ogg, .opus, .mp4 of .wav — dit zijn de gangbare formaten van de MediaRecorder API die browsers gebruiken.

  • Content-Type header: audio/webm, audio/ogg, audio/mpeg, etc.

  • Blob-URL: Tijdens de opname zelf wordt een tijdelijke blob:https://... URL aangemaakt. Deze staat niet in de Network-tab, maar is zichtbaar zolang de browsertab open is.

  • Grote POST-upload: Direct na het stoppen van de opname stuurt Finly het bestand naar de server. Dit is zichtbaar als een POST-verzoek met een grote payload in de Network-tab (filter: XHR/Fetch).

Hoe herken je dat een opname niet correct is opgeslagen?

  • Geen POST-verzoek zichtbaar in de Network-tab na het afronden van de opname — de upload heeft dan nooit plaatsgevonden.

  • POST-verzoek aanwezig, maar statuscode niet 200/201 — de upload is mislukt. Klik op het verzoek → tabblad Preview of Response voor de foutmelding.

  • Bestand wel in Cache Storage of IndexedDB, maar niet in de Finly interface — de upload is waarschijnlijk onderbroken.

  • Geen enkel audiobestand zichtbaar in Network (Media) of Application — de opname is mogelijk nooit gestart of direct verloren gegaan (bijv. door een browserfout).

Hoe lang blijft de cache bewaard?

  • Memory cache: Verdwijnt zodra de browsertab of browser wordt gesloten.

  • Disk cache (HTTP-cache): Blijft staan totdat de browser de cache automatisch opruimt op basis van beschikbare schijfruimte. Doorgaans enkele dagen tot weken.

  • Cache Storage (Service Worker): Blijft bestaan totdat de Service Worker de cache expliciet verwijdert, of totdat de gebruiker de browsercache handmatig wist.

  • IndexedDB: Blijft permanent staan totdat de app of de gebruiker de data verwijdert.

Conclusie: Zolang de tab open is en er geen hard refresh is gedaan, is de kans het grootst dat de opname nog terug te vinden is via Cache Storage of als blob in het geheugen.

Samenvatting snelle stappen

  1. Sluit de browser niet af en doe geen hard refresh.

  2. Open DevTools (F12).

  3. Ga naar Network → filter Media → vernieuw met F5 → zoek audiobestand.

  4. Niet gevonden? Ga naar Application → Cache Storage.

  5. Nog niet gevonden? Ga naar Application → IndexedDB.

  6. Check Network → XHR/Fetch op mislukte POST-uploads (statuscode ≠ 200/201).

  7. Gevonden bestand downloaden: rechtsklik op verzoek → Opslaan als.
